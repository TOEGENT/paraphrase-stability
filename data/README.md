# Data specification

## Назначение

Датасет используется для измерения сохранения смысла ответа
фиксированной SLM при эквивалентных преобразованиях вопроса.

## Формат хранения

- JSONL, кодировка UTF-8.
- Одна строка — один JSON-объект.
- Идентификаторы — строки.
- Вопросы и ответы сохраняются без ручного исправления.
- Модель, системная инструкция и настройки генерации
  фиксируются отдельно для всего набора.

| Файл | Содержимое |
|---|---|
| questions.jsonl | Исходные вопросы |
| answers.jsonl | Исходные ответы SLM |
| rephrased_questions.jsonl | Перефразы вопросов |
| rephrased_answers.jsonl | Ответы на перефразы |
| equivalents.jsonl | Эквивалентность ответов на принятые перефразы |

## 1. questions.jsonl

Обязательные поля:

- `question_id` — уникальный идентификатор исходной задачи.
- `question` — текст исходного вопроса.

```jsonl
{"question_id":"question-000001","question":"Анна выше Бориса. Вера ниже Бориса. Глеб выше Анны. Кто второй по росту?"}
```

## 2. answers.jsonl

Обязательные поля:

- `question_id` — ссылка на запись в questions.jsonl.
- `answer` — фактический ответ SLM на исходный вопрос.

```jsonl
{"question_id":"question-000001","answer":"Анна"}
```

В рамках одной версии набора каждый question_id имеет
не более одного исходного ответа.

## 3. rephrased_questions.jsonl

Обязательные поля:

- `question_id` — ссылка на исходный вопрос.
- `variant_id` — уникальный идентификатор перефраза.
- `question` — текст перефразированного вопроса.

Дополнительное поле:

- `transformation_type` — тип преобразования;
  требуется при анализе отдельных методов перефразирования.

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","question":"Глеб выше Анны. Борис ниже Анны, но выше Веры. Кто уступает по росту только одному человеку?","transformation_type":"syntactic_rewrite"}
```

## 4. rephrased_answers.jsonl

Обязательные поля:

- `question_id` — ссылка на исходный вопрос.
- `variant_id` — ссылка на запись в rephrased_questions.jsonl.
- `answer` — фактический ответ SLM на перефраз.

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","answer":"Анна"}
```

Каждый variant_id имеет не более одного ответа
в рамках одной версии набора.

## 5. equivalents.jsonl

Обязательные поля:

- `question_id` — ссылка на исходный вопрос.
- `variant_id` — ссылка на перефраз.
- `answer_equivalence` — сохраняет ли ответ на перефраз
  смысл исходного ответа.

Допустимые статусы:

| Статус | Значение |
|---|---|
| equivalent | Эквивалентность подтверждена |
| non_equivalent | Обнаружено существенное различие |
| unclear | Решение неуверенное; нужна дополнительная проверка |
| insufficient_context | Недостаточно контекста для сравнения |

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","answer_equivalence":"equivalent"}
{"question_id":"question-000001","variant_id":"question-000001-v2","answer_equivalence":"non_equivalent"}
{"question_id":"question-000001","variant_id":"question-000001-v3","answer_equivalence":"unclear"}
```

Эквивалентность ответов оценивается в контексте исходной задачи.
Правильность не является критерием эквивалентности.

## Связи между файлами

- question_id связывает исходный вопрос, исходный ответ
  и все варианты задачи.
- variant_id связывает перефраз, ответ на него и разметку.
- question_id одного variant_id должен совпадать во всех файлах.
- Ссылки на отсутствующие вопросы или варианты недопустимы.
- Дублирующиеся записи по соответствующему ID недопустимы.

На промежуточном этапе ответы и разметка могут отсутствовать.
Готовность набора к обучению проверяется отдельно.

## Вычисление целевой метки

Метка вычисляется из пяти файлов, а не записывается вручную
в каждую строку.

Для исходной пары «вопрос–ответ»:

- N — число вручную принятых перефразов с ответами.
- k — число таких вариантов с answer_equivalence = equivalent.
- target = k / N.

Исходный ответ не включается в N.

Отклонённые при ручной проверке перефразы исключаются.
Статусы unclear и insufficient_context требуют разрешения:
до него `target` остаётся `null`, а `N` включает эти варианты.

Для готовой метки необходимо N > 0.
Если проверок нет, метка не определена, а не равна нулю.

Неразрешённые случаи и их исключение документируются:
исключение может смещать оценку.

Обычная доля k/N предполагает равный вес принятых вариантов.

## Разделение выборок

- Разделение задаётся отдельно по question_id.
- Все варианты одной задачи находятся в одном split.
- Допустимые названия: train, val, test.
- Дубликаты исходных задач объединяются до разделения.
- Итоговый test используется после фиксации метода.

## Происхождение и версии

Для каждого релиза отдельно фиксируются:

- источники вопросов и исходные идентификаторы;
- условия использования данных;
- модель и настройки генератора перефразов;
- правила допустимых преобразований;
- точная версия целевой SLM и настройки генерации;
- версия оценщика и инструкции разметки;
- результаты ручного аудита;
- количество исключённых и неразрешённых вариантов.

Рекомендуемые теги: dataset-mvp-w1 … dataset-mvp-w4.

## Демонстрационные данные

Примеры в data/examples/ явно обозначаются как демонстрационные.
Вымышленные ответы не используются для обучения
или экспериментальной оценки.
