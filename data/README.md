# Data specification

## Назначение

Каталог хранит вопросы, ответы фиксированной SLM,
переформулировки, разметку и целевые метки для прогнозирования
сохранения смысла ответа при эквивалентных преобразованиях вопроса.

## Формат хранения

- JSONL, кодировка UTF-8.
- Одна строка — один JSON-объект.
- Идентификаторы хранятся как строки.
- Отсутствующие или ещё не определённые значения — `null`.
- Вопросы и ответы сохраняются без ручного исправления.
- Один релиз соответствует одной фиксированной конфигурации SLM.

## 1. questions.jsonl

Исходные вопросы.

Обязательные поля:

- `question_id` — уникальный идентификатор исходной задачи.
- `question` — текст исходного вопроса.

```jsonl
{"question_id":"question-000001","question":"Анна выше Бориса. Вера ниже Бориса. Глеб выше Анны. Кто второй по росту?"}
```

## 2. answers.jsonl

Ответы SLM на исходные вопросы.

Обязательные поля:

- `question_id` — ссылка на исходный вопрос.
- `answer` — фактический ответ SLM.

```jsonl
{"question_id":"question-000001","answer":"Анна"}
```

Для каждого исходного вопроса допускается один исходный ответ
в рамках фиксированной конфигурации генерации.

## 3. rephrased_questions.jsonl

Переформулированные вопросы.

Обязательные поля:

- `question_id` — ссылка на исходный вопрос.
- `variant_id` — уникальный идентификатор варианта.
- `question` — текст переформулировки.

Дополнительное поле:

- `transformation_type` — тип преобразования.
  Обязательно для анализа по типам преобразований.

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","question":"Глеб выше Анны. Борис ниже Анны, но выше Веры. Кто уступает по росту только одному человеку?","transformation_type":"syntactic_rewrite"}
```

## 4. rephrased_answers.jsonl

Ответы SLM на переформулированные вопросы.

Обязательные поля:

- `question_id` — ссылка на исходную задачу.
- `variant_id` — ссылка на переформулировку.
- `answer` — фактический ответ SLM.

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","answer":"Анна"}
```

## 5. annotations.jsonl

Разметка эквивалентности вопросов и ответов.

Обязательные поля:

- `question_id` — ссылка на исходную задачу.
- `variant_id` — ссылка на вариант.
- `question_equivalence` — эквивалентность переформулировки
  исходному вопросу.
- `answer_equivalence` — эквивалентность ответа на переформулировку
  исходному ответу.

Допустимые статусы:

- `equivalent`;
- `non_equivalent`;
- `unclear`;
- `insufficient_context`.

Если эквивалентность вопроса не подтверждена,
`answer_equivalence` устанавливается в `null`.

```jsonl
{"question_id":"question-000001","variant_id":"question-000001-v1","question_equivalence":"equivalent","answer_equivalence":"equivalent"}
{"question_id":"question-000001","variant_id":"question-000001-v2","question_equivalence":"equivalent","answer_equivalence":"non_equivalent"}
{"question_id":"question-000001","variant_id":"question-000001-v3","question_equivalence":"equivalent","answer_equivalence":"unclear"}
{"question_id":"question-000001","variant_id":"question-000001-v4","question_equivalence":"non_equivalent","answer_equivalence":null}
```

Правильность ответа не определяет семантическую эквивалентность.

## 6. targets.jsonl

Агрегированные метки для исходных пар «вопрос–ответ».

Обязательные поля:

- `question_id` — ссылка на исходную задачу.
- `k` — число эквивалентных проверочных ответов.
- `N` — число проверочных ответов с окончательной разметкой.
- `target` — доля `k / N`.
- `split` — `train`, `val` или `test`.

```jsonl
{"question_id":"question-000001","k":8,"N":10,"target":0.8,"split":"train"}
```

### Правила подсчёта

- В N включаются только варианты с
  `question_equivalence = equivalent` и окончательным
  `answer_equivalence = equivalent` или `non_equivalent`.
- В k включаются только варианты с
  `answer_equivalence = equivalent`, принятые в N.
- Исходный ответ не входит в k и N.
- Неэквивалентные вопросы исключаются.
- Неясные случаи требуют проверки; они не считаются
  автоматически неэквивалентными.
- Для готовой метки должны выполняться N > 0 и 0 <= k <= N.
- До завершения разметки k, N и target хранятся как null.
- Если неясные случаи не удалось разрешить, исключение
  документируется: оно может смещать оценку.

Обычная метка k/N соответствует равному весу принятых вариантов.
Иное взвешивание требует отдельного описания и поля метки.

## Проверка связей

1. Каждый question_id в остальных файлах существует
   в questions.jsonl.
2. Каждый variant_id в ответах и разметке существует
   в rephrased_questions.jsonl.
3. question_id одного variant_id согласован во всех файлах.
4. Идентификаторы записей не дублируются внутри соответствующих файлов.
5. k, N и target воспроизводятся из annotations.jsonl.

## Правила разделения

1. Все варианты одной задачи находятся в одном split.
2. Дубликаты и эквивалентные исходные задачи из разных источников
   объединяются перед разделением.
3. Split хранится в targets.jsonl и применяется ко всем
   связанным записям.
4. Итоговый test используется только после фиксации метода.

## Происхождение и версии

В метаданных каждого релиза фиксируются:

- источники задач, исходные идентификаторы и лицензии;
- версия датасета;
- модель и настройки генератора преобразований;
- инструкции генератору;
- model_version_id и точная конфигурация целевой SLM;
- системная инструкция и параметры decoding;
- оценщик и protocol_version_id;
- правила отбора, распределение типов преобразований;
- результаты ручного аудита и количество исключений.

Происхождение отдельных вопросов хранится в отдельном
реестре, связанном через question_id.

Рекомендуемые теги релизов: dataset-mvp-w1 … dataset-mvp-w4.

## Демонстрационные данные

Файлы в data/examples/ служат для проверки формата.
В README этой папки явно указывается, являются ли ответы
вымышленными. Вымышленные записи не используются
для обучения и экспериментальной оценки.
