# paraphrase-stability

Проект исследует, можно ли по одному вопросу и ответу небольшой языковой модели (SLM) предсказать, изменится ли **смысл ответа**, если тот же вопрос задать другими словами. Краткая научная постановка — в [abstract](docs/abstract.md), понятный пример и близкие работы — в [user story](docs/user-story.md).

Если совсем грубо: берём вопрос, спрашиваем модель, потом задаём ей тот же вопрос в нескольких других формулировках и смотрим, насколько часто смысл ответа остаётся прежним. По этим проверкам собираем данные и пробуем обучить небольшую модель предсказывать устойчивость ответа по исходной паре «вопрос — ответ». Это исследовательский эксперимент, а не готовая система проверки ответов.

## Как ориентироваться в репозитории

- [scripts/README.md](scripts/README.md) — с чего начать и в каком порядке запускать весь процесс.
- `configs/` — настройки моделей, экспериментов и способов перефразирования; `prompts/` — инструкции для генерации и сравнения ответов.
- `scripts/` — команды для сборки данных, подсчёта устойчивости, обучения и оценки; `src/slm_answer_stability/` — код, который они используют.
- [data/README.md](data/README.md) и `data/examples/` — формат данных и маленькие примеры; `work/` — рабочие файлы запусков.
- `docs/` — подробности методов и форматов; `tests/` — проверки кода; `results/` — правила хранения результатов; `paper/` — набросок статьи.

## Зачем тратить внимание на эту тему?

Представьте, что бот ответил на вопрос о возврате товара: «Обратитесь в магазин в течение 14 дней». Человек может спросить то же самое как «Как оформить возврат?», и бот иногда даст другой по смыслу совет. Для прямой проверки приходится создавать несколько равнозначных формулировок, снова запускать SLM и сравнивать ответы; на большом наборе вопросов это затратно.

Близкие исследования уже измеряют чувствительность моделей к перефразированию, поэтому утверждать, что работ на эту тему нет, нельзя. Вопрос этого проекта уже: **можно ли предсказать устойчивость ответа до дополнительных запусков SLM и использовать прогноз для отбора задач на подробную проверку?** Это остаётся исследовательской гипотезой.

## Что означает `k/N`?

Для исходного вопроса получаем исходный ответ SLM, затем вручную отбираем перефразы, сохраняющие смысл вопроса, и получаем ответы той же SLM на них:

- `N` — число принятых перефразов с ответами;
- `k` — число этих ответов, совпадающих по смыслу с **исходным** ответом;
- `k/N` — наблюдаемая доля совпадений в проверенном наборе.

Исходный ответ не входит в `N`. Если два ответа из трёх совпали с ним, метка равна `2/3`; она может быть высокой даже при **неверном** исходном ответе. При неразрешённой оценке смысла итоговая метка не выдаётся. Эта доля зависит от способа создания и отбора перефразов, числа проверок, модели и настроек генерации; она не является универсальной вероятностью для любых формулировок.

## Где нужна MLP и что будет результатом?

MLP получает эмбеддинги только исходных вопроса и ответа и прогнозирует непрерывную долю `k/N` — это **регрессия**, а не классификация. Перефразы и ответы на них нужны при создании обучающих меток, но не подаются MLP при прогнозе для нового вопроса. Возможное применение — сначала проверять задачи с низким прогнозом устойчивости, когда бюджет на полные проверки ограничен.

Результатом исследования должны стать проверенный набор с `k`, `N` и решениями по вариантам, обученный предиктор и сравнение с простыми базовыми методами на новых задачах. Пользу MLP нужно подтвердить ошибкой и калибровкой прогноза, качеством отбора задач и полной стоимостью вычислений; текущий README не заявляет уже полученного преимущества. MLP не определяет правильность ответа и не заменяет прямую проверку там, где нужен фактический `k/N` для конкретного вопроса.
