# 100 структурных перефразов линейного уравнения

`scripts/generate_linear_paraphrases.py` принимает одно уравнение или JSONL
исходных задач. По умолчанию создаётся **100 дополнительных записей** на задачу:
10 семейств по 10 вариантов. Исходная запись в эти 100 не входит.
Нужен только Python 3.10+: установки проекта, SymPy, Mathematics Dataset
и запросов к языковой модели для этого скрипта не требуется.

Поддерживаются линейные уравнения с одной неизвестной и единственным решением.
Это преобразования математической записи; они могут менять сложность решения
и число операций. Протокол следует учитывать при интерпретации метки `k/N`.

## Команды

Примеры команд для будущего запуска из корня репозитория:

```sh
python3 scripts/generate_linear_paraphrases.py --equation '2*x + 3 = 7' --seed 42 --output work/one_equation_variants.jsonl
```

Для исходных задач из основного README:

```sh
python3 scripts/generate_linear_paraphrases.py --input work/linear_sources.jsonl --variants-per-question 100 --seed 42 --output work/linear_variants_100.jsonl
```

Можно передавать `question` или `equation`. `question_id` обязателен для JSONL;
в режиме `--equation` он задаётся через `--question-id` (по умолчанию
`linear-000001`). Поле `answer` необязательно: точное решение вычисляется самим
скриптом. Если эталон указан, он проверяется до генерации вариантов.

```json
{"question_id":"q1","question":"Solve 2*r + 3 = 7 for r.","answer":"2"}
```

Другие допустимые формы: `2*x + 3 = 7` и `Solve for x: $2*x + 3 = 7$.`.
Поддерживаются `+`, `-`, `*`, `/`, скобки, целые и обычные десятичные числа,
рациональные дроби, а также неявное умножение `2x` и `2(x - 3)`.
Степени, функции, системы, несколько неизвестных, нелинейные произведения,
переменные знаменатели, противоречивые и неопределённые уравнения отклоняются.
Десятичная запись трактуется как точная дробь; числовой допуск не используется.

Если в строке есть `structure.source.base_equations`, скрипт проверяет и её:
требуется одна запись `Eq` с `children.left.text` и `children.right.text`,
задающая то же единственное решение. Неверная структура вызывает ошибку.
Сам скрипт умеет разбирать видимое уравнение без заранее сохранённой структуры.
Поэтому он работает и с `--format plain` у `generate_math_tasks.py`, обходя
отсутствующий в официальной версии DeepMind API `capture_question_structure`.
Условия с дополнительными определениями в естественном языке не поддерживаются.

## Разбор по частям

Выражение разбирается ограниченным AST-парсером без `eval`. Отдельно доступны:

- числа с их точными рациональными значениями;
- неизвестная;
- операции сложения, вычитания, умножения, деления и унарного знака;
- вложенные группы выражений;
- верхнеуровневые слагаемые со знаками;
- приведённые коэффициент при неизвестной и свободный член каждой стороны.

Например, у `2*x - 3 + 4` слагаемые — `+2*x`, `-3`, `+4`, а приведённые
коэффициент и свободный член равны `2` и `1`. Генератор работает со слагаемыми
и группами, сохраняя дерево операций; приведение используется для проверки,
а не для принудительного упрощения всех вариантов до одного вида.

## Семейства преобразований

Иллюстрации ниже относятся к `2*x + 3 = 7` и не являются отчётом о запуске.

| Семейство | Изменение | Пример |
| --- | --- | --- |
| `permute_terms` | Перестановка слагаемых с сохранением их знаков | `3 + 2*x = 7` |
| `transfer_terms` | Одинаковая добавка и перенос слагаемого со сменой знака | `3 + 5 = 7 + 5 - 2*x` |
| `split_constants` | Разбиение постоянного слагаемого на сумму | `2*x + 3 = 2 + 5` |
| `split_coefficients` | Разбиение коэффициента при неизвестной | `5*x - 3*x + 3 = 7` |
| `group_terms` | Компенсирующая пара чисел и новая группировка | `(2*x + 5) + (3 - 5) = 7` |
| `multiply_sides` | Умножение обеих сторон на ненулевое число | `3*(2*x + 3) = 3*7` |
| `divide_sides` | Деление обеих сторон на ненулевое число | `(2*x + 3)/3 = 7/3` |
| `add_constant` | Прибавление одинакового числа | `(2*x + 3) + 5 = 7 + 5` |
| `add_linear_expression` | Прибавление одинакового линейного выражения | `(2*x + 3) + (3*x + 5) = 7 + (3*x + 5)` |
| `distribute` | Масштабирование суммы с раскрытием части скобок | `3*((2*x + 3) + 5) = 3*7 + 15` |

Обмен сторон равенства сочетается с каждым семейством. У коротких уравнений
может быть меньше десяти чистых перестановок. В этом случае `permute_terms`
дополнительно разбивает одно слагаемое `T` на `(T-c)+c`, затем переставляет
полученные части. Этот шаг явно записывается в `transformation_steps`.
Часть семейств использует общие математические правила в разных оформлениях;
семейства не являются независимыми математическими механизмами.

Дубли исключаются по тексту уравнения без пробелов, включая исходную запись.
Одинаковые после упрощения, но по-разному записанные уравнения намеренно
сохраняются: именно устойчивость к таким изменениям и исследуется.
Числа параметров ограничены небольшими диапазонами; не используются
умножение на ноль, деление на выражения с неизвестной и изменение множества корней.

## Выход и оценщик

Одна строка выхода соответствует одному варианту. Основные поля:

- `question_id`, `variant_id`, `question_original`, `question_transformed`;
- `reference_answer` — эталон отдельно от текста вопроса;
- `transformation_type: linear_equivalence`, `transformation_mode: structure`;
- `transformation_family`, `transformation_target`, `transformation_steps`;
- `structure.source.base_equations` — дерево полученного равенства;
- `source_question` и `source_variable` — вход до нормализации;
- `equivalence_verifier: exact_affine_fraction_v1`, `paraphrase_review: pending`.

Для совместимости с `check_math_answer_correctness.py` неизвестная исходной
задачи и всех её вариантов приводится к `x`, формат — `Solve for x: $... = ...$.`.
Десятичные числа во входном выражении заменяются точными дробями, чтобы
существующий проверяющий скрипт не округлял длинные литералы через `float`.
Оригинал для эксперимента — нормализованное исходное уравнение, а не одна
из сотни дополнительных записей. При сравнении с другими прогонами нужно
учитывать эту нормализацию имени неизвестной, чисел и оформления вопроса.

Каждый вариант повторно разбирается из итогового текста. Для двух сторон
`a*x+b` и `c*x+d` проверяются `a != c` и точное совпадение `(d-b)/(a-c)`
с исходным решением. Одной подстановки известного корня было бы недостаточно:
например, тождество `0=0` тоже пропускает любую подстановку, но не имеет
того же единственного решения.

После просмотра вариантов выставляются `approved`/`rejected`, затем применяются
существующие `generate_answers.py`, `check_math_answer_correctness.py`,
`equivalence_generation.py` и `compute_k_N.py`. `transformation_target`
передаёт семейство преобразования в файл ответов существующим кодом.
При сохранении всех 100 вариантов группа содержит 101 ответ и `N=100`
для каждого якоря. Отклонение вариантов меняет `N`.
Все якоря одной задачи должны оставаться в одной части train/val/test.
Правильность решения и устойчивость ответов по-прежнему оцениваются отдельно.

Выходной файл должен быть новым. Ошибки входных строк обнаруживаются до его
создания. Одинаковые вход, `seed` и версия Python дают одинаковые результаты;
`--variants-per-question` допускает от 1 до 100, распределяя квоты между
семействами с разницей не более одного.

Для проверки подготовлен `tests/test_linear_paraphrases.py`: сто уникальных
вариантов, баланс семейств, проверка существующим независимым верификатором,
нулевые и дробные корни, структуры, воспроизводимость и защита входных файлов.
