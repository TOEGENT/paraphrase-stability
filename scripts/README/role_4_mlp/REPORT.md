# Роль 4: отчёт по MLP на линейных уравнениях (варианты А, Б, Ц)

Тестовая часть (`test`) в этих экспериментах **не использовалась**. Все числа получены на train и val. Результаты лежат локально в `work/` (в git не входят).

## Данные

- Вход: `linear_answers.jsonl`, 100 уравнений Mathematics Dataset (`algebra.linear_1d`) × 100 вариантов, ответы `qwen3.5-9b`. Это сырые ответы без `k/N`.
- Из 10 000 строк удалено 10 с неразбираемым ответом (5 раз `No solution`, 5 цепочек вида `y = -2560/512 = -5`). Остальные ответы разобраны точной дробью.
- Метки: каждый ответ (исходный и на вариант) — якорь, `k` = число совпадающих итоговых значений среди остальных ответов того же уравнения, `target = k/N`, `N` ≈ 100. Получено 10 090 якорей.
- Разбиение по уравнению (`compute_k_N.py`, seed 42): train 78 / val 11 / test 11 уравнений (7 871 / 1 110 / 1 109 якорей).
- Правильность ответов SLM (точная подстановка): исходные 41 из 100, варианты 3 246 из 10 000 (около 32%). Средний `target` 0,16–0,17, распределение скошено вправо (0,0 у 42% якорей).
- Верные ответы совпадают между собой, неверные почти всегда расходятся: средний `target` у верных 0,42, у неверных 0,05. Константа, зависящая только от правильности ответа, дала бы MAE 0,087 (оценка потолка по всем данным).

## Вариант А: одно разбиение, val

Конфиг `configs/mlp.example.json` (hidden 64, dropout 0,1), эмбеддинги `multilingual-e5-base` (запрос + ответ), лучшая эпоха 39.

| | MAE | RMSE |
|---|---|---|
| Константа (среднее train, 0,162) | 0,169 | 0,216 |
| MLP | 0,104 | 0,145 |

Val состоит из 11 уравнений, поэтому оценка шумная и оптимистична (см. Б).

## Вариант Б: групповая 5-fold кросс-валидация

Данные: train + val (89 уравнений), 3 seed × 5 фолдов. Ранняя остановка по внутренней отложенной группе. Значения: среднее по 15 прогонам ± разброс (фолды и seed не независимы, это не доверительный интервал).

**Фолды по уравнению**

| Модель | MAE | RMSE | Spearman |
|---|---|---|---|
| Константа | 0,163 ± 0,021 | 0,206 | — |
| Ridge, [вопрос, ответ] | 0,127 ± 0,022 | 0,167 | 0,54 |
| MLP, [вопрос, ответ] | 0,115 ± 0,019 | 0,157 | 0,58 |
| MLP, только вопрос | 0,128 ± 0,014 | 0,167 | 0,42 |
| MLP, только ответ | 0,130 ± 0,022 | 0,180 | 0,52 |

**Фолды по корню** (уравнения с одинаковым решением в одном фолде, 52 группы)

| Модель | MAE | RMSE | Spearman |
|---|---|---|---|
| Константа | 0,165 ± 0,021 | 0,207 | — |
| Ridge, [вопрос, ответ] | 0,133 ± 0,021 | 0,179 | 0,46 |
| MLP, [вопрос, ответ] | 0,128 ± 0,022 | 0,178 | 0,46 |
| MLP, только вопрос | 0,130 ± 0,026 | 0,171 | 0,37 |
| MLP, только ответ | 0,145 ± 0,025 | 0,202 | 0,35 |

Выводы: MLP лучше константы при любом разбиении; при разбиении по корню ошибка MLP растёт (0,115 → 0,128), то есть часть результата объясняется общими корнями; преимущество MLP над ridge маленькое; вопрос и ответ по отдельности хуже, чем вместе.

## Вариант Ц: взаимодействия и ручные признаки

Та же схема кросс-валидации. Ручные признаки (15 штук) считаются только по тексту вопроса и ответа, без решения уравнения: длина и число чисел в вопросе, максимум и логарифм суммы модулей чисел, число скобок, умножений, минусов и плюсов, число букв-переменных, длина ответа, модуль и логарифм значения ответа, знак, целочисленность, превышает ли ответ максимум чисел вопроса.

**Фолды по уравнению**

| Модель | MAE | RMSE | Spearman |
|---|---|---|---|
| Константа | 0,163 ± 0,021 | 0,206 | — |
| MLP, эмбеддинги + `q*a` + `|q−a|` | 0,115 ± 0,021 | 0,157 | 0,58 |
| **MLP, ручные признаки** | **0,102 ± 0,021** | **0,147** | **0,69** |
| MLP, эмбеддинги + ручные | 0,103 ± 0,021 | 0,147 | 0,67 |
| GBM, ручные признаки | 0,104 ± 0,023 | 0,155 | 0,66 |
| GBM, ручные + флаг правильности (диагностика) | 0,060 ± 0,011 | 0,094 | 0,86 |

**Фолды по корню**

| Модель | MAE | RMSE | Spearman |
|---|---|---|---|
| Константа | 0,165 ± 0,021 | 0,207 | — |
| MLP, эмбеддинги + `q*a` + `|q−a|` | 0,129 ± 0,023 | 0,179 | 0,46 |
| **MLP, ручные признаки** | **0,103 ± 0,017** | **0,150** | **0,66** |
| MLP, эмбеддинги + ручные | 0,109 ± 0,018 | 0,157 | 0,61 |
| GBM, ручные признаки | 0,116 ± 0,021 | 0,180 | 0,55 |
| GBM, ручные + флаг правильности (диагностика) | 0,060 ± 0,010 | 0,095 | 0,84 |

Выводы: признаки `q*a` и `|q−a|` не помогли; ручные признаки точнее эмбеддингов, причём разрыв больше при строгом разбиении по корню (0,103 против 0,128). Строка «флаг правильности» вычисляется решением уравнения и признаком метода быть не может: это только ориентир, сколько информации несёт правильность ответа.

## Ограничения

- 89 уравнений в кросс-валидации, 11 в val и 11 в test: оценки шумные.
- Ручные признаки подобраны после просмотра результатов Б на тех же 89 уравнениях, возможен небольшой оптимистичный сдвиг.
- Гиперпараметры MLP не подбирались (конфиг по умолчанию).
- Перекрытие корней между CV-пулом и test не проверялось.
- Метка `k/N` показывает согласованность ответов, а не правильность; низкая правильность SLM (около 32%) делает метку близкой к «верен ли ответ».
- `analyze_predictions.py` не рассчитан на якорный формат (требует `variants`), для этих данных не запускался.
- Результаты относятся к одной SLM и одной теме (`algebra.linear_1d`).

## Как воспроизвести

Из корня репозитория, окружение с CUDA-версией torch:

```powershell
python scripts/equivalence_generation.py --input work/linear_answers_clean.jsonl --output work/linear_equivalence.jsonl
python scripts/compute_k_N.py --input work/linear_equivalence.jsonl --seed 42 --train 0.8 --val 0.1 --test 0.1 --output work/linear_anchors.jsonl
python scripts/build_embeddings.py --anchors-input work/linear_anchors.jsonl --splits-dir work/linear_splits --output-dir work/linear_features --device cuda:0 --batch-size 64
python scripts/train_mlp.py --splits-dir work/linear_splits --features-dir work/linear_features --config configs/mlp.example.json --output-dir work/linear_mlp --device cuda:0
python scripts/group_cv.py --splits-dir work/linear_splits --features-dir work/linear_features --output work/cv_source.json --group-by source
python scripts/group_cv.py --splits-dir work/linear_splits --features-dir work/linear_features --output work/cv_root.json --group-by root
python scripts/group_cv.py --splits-dir work/linear_splits --features-dir work/linear_features --output work/cvC_source.json --group-by source --extended
python scripts/group_cv.py --splits-dir work/linear_splits --features-dir work/linear_features --output work/cvC_root.json --group-by root --extended
```

`work/linear_answers_clean.jsonl` — копия `linear_answers.jsonl` без 10 строк с неразбираемым ответом.
