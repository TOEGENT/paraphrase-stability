# Инструкция разработчику скрипта оценки

## Цель

Создать скрипт, который загружает обученный MLP, получает
прогнозы на отложенных данных и сравнивает их с измеренной
устойчивостью ответов.

Сначала изучить существующий код обучения и формат датасета.
Не создавать альтернативную архитектуру или формат без необходимости.

## Входные данные

- Checkpoint предиктора.
- Тестовые пары или подготовленные признаки.
- Число эквивалентных ответов k и число проверок N.
- Идентификатор исходной задачи task_id.
- Конфигурация извлечения признаков.
- Параметры базовых методов, полученные только на train.

Целевая метка: y = k / N.

## Что реализовать

1. Проверить формат данных:
   - совпадают размеры массивов;
   - нет NaN и бесконечностей;
   - N > 0 и 0 <= k <= N;
   - присутствуют идентификаторы задач.

2. Загрузить модель и сохранённую обработку признаков.
   - Использовать ту же архитектуру, что при обучении.
   - Не обучать эмбеддер, PCA или нормализацию на test.
   - Перевести модель в режим оценки и отключить градиенты.

3. Получить прогнозы пакетами.

4. Сравнить MLP с:
   - постоянным прогнозом средней метки train;
   - сохранённой линейной моделью, если она доступна.

5. Рассчитать:
   - MAE;
   - RMSE;
   - улучшение относительно базовых методов;
   - калибровку: средний прогноз и среднюю метку по интервалам;
   - результаты по источникам задач и типам преобразований,
     если соответствующие поля доступны.

6. Учесть зависимость примеров:
   - основной результат считать с равным весом исходных задач;
   - доверительные интервалы получать bootstrap по task_id,
     сохраняя все строки выбранной задачи вместе.

7. Измерить время оценки:
   - отдельно извлечение признаков и инференс MLP;
   - если признаки уже готовы, явно сообщить, что их стоимость
     не включена.

## Выходные файлы

- metrics.json — метрики, конфигурация и размеры выборки.
- predictions.csv — task_id, k, N, target, prediction,
  абсолютная ошибка и прогнозы базовых методов.
- calibration.csv — интервалы, число примеров,
  средний прогноз и средняя метка.
- calibration.png — график калибровки.
- error_analysis.csv — примеры с наибольшей ошибкой.
- report.md — краткое описание результатов и ограничений.

## Запуск

Сделать CLI с параметрами:

- путь к данным;
- путь к checkpoint;
- путь к конфигурации;
- директория результатов;
- batch size;
- устройство;
- seed для bootstrap.

Запуск должен воспроизводиться одной командой.

## Ограничения

- Скрипт не обучает и не подбирает модели.
- Не использует test для настройки порогов или признаков.
- Не интерпретирует устойчивость как правильность.
- Не считает метку k/N точной вероятностью:
  она получена по конечному числу проверок.
- На этапе разработки запускать скрипт на validation.
  Итоговый test использовать после фиксации метода.

## Проверка готовности

На маленьком искусственном примере проверить:

- при prediction = target ошибка равна нулю;
- постоянный прогноз рассчитан по train;
- дублирование строк одной задачи не увеличивает её общий вес;
- некорректные данные вызывают понятную ошибку.

После реализации показать команду запуска, пример отчёта
и список выполненных проверок.
