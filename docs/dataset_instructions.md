# Инструкция по сбору датасета

## Цель

Собрать данные для обучения MLP, предсказывающего по одной паре
«вопрос–ответ» долю эквивалентных переформулировок, на которые
фиксированная SLM отвечает тем же смыслом.

Правильность ответа и его устойчивость рассматриваются отдельно.

## 1. Определение критериев для пар «вопрос–ответ»

### Вопрос

Включаем вопросы, которые:

- задают одну информационную потребность;
- имеют однозначную интерпретацию;
- требуют одного итогового результата;
- позволяют переформулировать текст без изменения условий задачи.

Вопрос может содержать несколько условий, если требует одного результата.

### Ответ

Для первого MVP включаем ответы, которые:

- выражают один итоговый результат: сущность, число, категорию
  или одно утверждение;
- допускают однозначное сравнение по смыслу.

Неправильный ответ допустим.

Неоднозначные ответы, отказы, ошибки генерации и обрезанные ответы
помечаем отдельно. Их исключение из основной выборки документируем.

### Результат этапа

Правила включения и исключения с примерами.

## 2. Определение критериев для методов перефразирования

Преобразование должно сохранять:

- исходную информацию;
- сущности и числовые значения;
- отношения, условия, отрицания и оговорки;
- требования задачи и формат ответа.

Допустимые методы:

- лексические замены;
- изменение синтаксиса;
- перестановка условий без изменения хронологии;
- изменение стиля;
- сокращение или расширение изложения без потери или добавления информации;
- изменение представления: абзац, список, таблица, JSON.

Недопустимы:

- добавление подсказок и решения;
- изменение фактов или требований;
- удаление существенных условий;
- добавление инструкций вроде «думай пошагово», если их не было.

Для каждого метода задаём примеры допустимых и недопустимых изменений.
Заранее определяем число вариантов каждого типа и их веса
в итоговой оценке устойчивости.

### Результат этапа

Каталог преобразований и правила проверки сохранения смысла.

## 3. Сбор данных по критерию 1

1. Выбрать источники задач и сохранить их происхождение.
2. Отобрать вопросы по установленным критериям.
3. Удалить дубликаты и объединить близкие варианты одной задачи.
4. Зафиксировать SLM, системную инструкцию, greedy decoding
   и лимит ответа.
5. Проверить воспроизводимость на повторных запусках.
6. Получить исходный ответ для каждого вопроса.
7. Проверить соответствие ответов критериям первого MVP.
8. Разделить исходные задачи на train, validation и test.

Все варианты одной задачи должны оставаться в одном split.
Одинаковые исходные задачи из разных источников также не должны
попадать в разные splits.

### Результат этапа

Исходные пары «вопрос–ответ» с task_id, источником, split
и конфигурацией генерации.

## 4. Настройка оценщика

Нужны две отдельные проверки.

### Проверка вопросов

Оценщик определяет, сохраняет ли перефраз информацию и требования
исходного вопроса по критериям этапа 2.

### Проверка ответов

Оценщик определяет, выражают ли два ответа один итоговый смысл
в контексте задачи.

Сохраняются существенные числа, отрицания, условия и оговорки.
Совместимость утверждений не равна их эквивалентности.
Правильность не используется как критерий совпадения.

### Настройка

1. Создать небольшую пилотную выборку преобразований и ответов.
2. Вручную разметить её, включая сложные и неэквивалентные пары.
3. Зафиксировать инструкцию и конфигурацию оценщика.
4. Сравнить его решения с ручной разметкой.
5. Уточнить правила на калибровочной части.
6. Проверить качество на отдельной контрольной части.

Использовать три решения:

- equivalent;
- different;
- uncertain.

Неясные случаи направлять на ручную проверку.
Не считать их автоматически различающимися.

### Результат этапа

Проверенный оценщик, версия инструкции и отчёт о качестве.

## 5. Генерация перефразов

1. Для каждой задачи создать заданное число вариантов
   по каталогу преобразований.
2. Сохранить тип преобразования и настройки генератора.
3. Удалить точные дубликаты, включая повтор исходного вопроса.
4. Вручную проверить сохранение смысла и условий вопроса перед запуском SLM.
5. Неподходящие варианты отклонить.
6. При необходимости сгенерировать замены.
7. Получить ответы целевой SLM на принятые варианты.

Системную инструкцию и настройки целевой SLM сохранять неизменными.

### Результат этапа

Проверенные варианты вопросов и ответы на них.

## 6. Проверка эквивалентности и разметка

1. Сравнить каждый проверочный ответ с исходным.
2. Присвоить метку 1 при эквивалентности и 0 при различии.
3. Разрешить неясные случаи вручную.
4. Выполнить выборочный ручной аудит принятых решений.
5. Рассчитать число эквивалентных ответов k и число проверок N.
6. Вычислить target = k / N.

Исходный ответ не включается в N.
Отклонённые перефразы не включаются в N.
Для каждой задачи сохраняется фактическое число проверок.

Если категории преобразований взвешиваются неодинаково,
использовать заранее определённую взвешенную оценку
и отдельно сохранять обычную долю k/N.

### Сохраняемые данные

- task_id и variant_id;
- источник и split;
- исходный вопрос и ответ;
- преобразованный вопрос и ответ;
- тип преобразования;
- решения оценщика и ручного аудита;
- k, N и target;
- версии генератора, целевой SLM и оценщика;
- настройки и статус каждого запуска.

### Результат этапа

Версионированный датасет для обучения и оценки MLP.

## Критерии готовности датасета MVP

- Правила отбора и преобразований записаны.
- Происхождение всех задач известно.
- Генерация воспроизводима.
- Выполнен ручной аудит вопросов и ответов.
- Нет пересечения задач между splits.
- Метки вычисляются из сохранённых решений.
- Показаны распределение меток и количество исключённых случаев.
- Итоговый test не используется для настройки метода.
